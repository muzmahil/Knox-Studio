Knox System Architecture & Overview

Knox is a dual-runtime, modern digital audio workstation designed for high-performance audio synthesis, sample manipulation, and reactive UI composition. Its architecture couples a C++20 real-time native engine with a .NET 10 cross-platform user interface via a zero-overhead C Foreign Function Interface (FFI).

High-Level Architectural Topology

+---------------------------------------------------------------------------------------------------+ | KNOX USER INTERFACE (.NET 10) | | | | [ Knox.App (Avalonia 12) ] <--- Data Binding ---> [ Knox.Presentation (MVVM ViewModels) ] | | | | | | +-- Custom DrawingContext Controls v | | (Waveforms, Piano Roll, Meters) [ Knox.Application (Ports & DTOs) ] | | | | | v | | [ Knox.Infrastructure (P/Invoke & IO) ] | +-----------------------------------------------------------------+---------------------------------+ | C Foreign Function Interface | (Zero Garbage Collection) +-----------------------------------------------------------------v---------------------------------+ | KNOX NATIVE CORE (C++20 DLL) | | | | [ SPSC Command Queue ] --- (Lock-Free FIFO) ---> [ Hard Real-Time Audio Render Thread ] | | | | | +---------------------------------------------------+--------------------+ | | | | | | | v v v | | [ Timeline Engine ] [ Instrument Voices ] [ Audio FX Graph ] | | - Audio Clips (Signalsmith Warp) - 10 Built-in Synths - 10 Built-in FX | | - MIDI Clips (Sample-accurate) - PolyBLEP & FM Engines - Parallel Racks | | - Audio-to-MIDI Transcription - Voice Stealing Manager - VST3 / AU Host | | | | | | | +-----------------------------------+------------------------------------+ | | | | | v | | [ Master Bus & True Peak Limiter ] | | | | | v | | [ miniaudio Hardware Driver (WASAPI/CoreAudio/ALSA) ] | +---------------------------------------------------------------------------------------------------+

Lock-Free Communication C ABI & Ring Queues The UI thread and audio render thread never block one another. All commands, parameter automation, and playhead movements travel via single-producer single-consumer (SPSC) lock-free ring buffers using acquire-release atomics.

Advanced DSP & Modulation Native DSP Subsystem Equipped with 10 built-in sound generators, 10 dynamic and spatial audio effects, Signalsmith time-stretching with transient preservation, YIN pitch tracking, and a 32-channel modular CV routing matrix.

Build Matrix & Platform Commands

Knox compiles natively on Windows 10/11 (x64/ARM64), macOS 12+ (Apple Silicon/Intel), and Linux (x86_64). Both the native C++ engine and the managed C# UI are built with standardized CLI tools.

Toolchain Prerequisites

  • C++ Compiler: MSVC v143 (Visual Studio 2022), Apple Clang 14+, or GCC 13+ with C++20 support.
  • Build Generator: CMake 3.25 or newer.

  • Audio Driver Libraries: WASAPI (Windows built-in), CoreAudio (macOS built-in), or ALSA / libasound2-dev (Linux).

Hard Real-Time Audio Rules (AR-1 to AR-9)

The native Knox audio engine executes inside a hard real-time operating system thread. Missing an audio buffer deadline causes audible dropouts, clicks, or glitches. To guarantee sub-3ms latency without failure, the engine strictly enforces rules AR-1 through AR-9.

⚠️ Hard Real-Time Constraint
Any code path reachable from knox_engine_render() must execute in bounded, deterministic time ($O(1)$ or $O(N)$ with fixed small $N$). Non-deterministic operations violate these rules and will fail code review.
Rule ID Constraint Title Detailed Engineering Requirement
AR-1 Zero Dynamic Allocation No calls to malloc, calloc, free, new, delete, or resizing STL containers (std::vector::push_back, std::string) on the audio thread. All memory must be pre-allocated during device creation.
AR-2 Zero Blocking & Mutexes No std::mutex, std::condition_variable, or OS locks. Priority inversion can stall the audio thread indefinitely. Use lock-free atomics and SPSC queues.
AR-3 Zero File & Network I/O Never call printf, file read/write, disk logging, or network socket operations from the render loop. File I/O belongs exclusively to background worker threads.
AR-4 Zero C++ Exceptions Throwing or catching exceptions on the audio thread incurs unbounded runtime overhead and stack unwinding. Error codes (NotaResult) are used exclusively.
AR-5 Fixed Scratch Buffers All intermediate DSP processing buffers are pre-allocated to maximum buffer sizes (e.g. 2048 frames) and memory-aligned (32/64 bytes) for SIMD AVX2/NEON vectorization.
AR-6 Cache Locality & SoA Store voice states and sample buffers sequentially in memory (Structure of Arrays) to maximize L1/L2 CPU cache hit rates and eliminate pointer chasing.
AR-7 Denormal Prevention DSP filter loops must enable hardware Flush-to-Zero (FTZ) and Denormals-are-Zero (DAZ) flags to prevent microcode trap slowdowns when IIR decay approaches zero.
AR-8 Lock-Free SPSC Queuing All communication between UI/control threads and the audio thread passes through Single-Producer Single-Consumer lock-free ring buffers using std::memory_order_release and std::memory_order_acquire.
AR-9 Bounded Execution Time Total block processing time must remain comfortably below the hardware buffer duration ($t_{ ext{render}} < 0.7 imes t_{ ext{deadline}}$) across all CPU loads.
Knox Documentation > Audio Engine > Render Loop

Hard Real-Time Audio Render Loop

The render loop is invoked synchronously by the underlying audio driver (via miniaudio) whenever hardware output buffers require replenishment. Every iteration processes exactly $N$ audio frames across all active tracks.

Step-by-Step Render Loop Sequence

Hardware Interrupt (miniaudio callback) | +--> Step 1: Drain SPSC Command Queue (Pointers, parameter automation, seeks) | +--> Step 2: Advance Transport (Calculate song position beats & tempo interpolation) | +--> Step 3: Dispatch MIDI Events (Timeline clips + hardware MIDI input) | +--> Step 4: Evaluate Modulation Matrix (Update 32 LFOs & Envelope Followers) | +--> Step 5: Process Instrument Tracks (Synthesizers generate audio into track buffers) | +--> Step 6: Process Audio Tracks (Signalsmith Warp engine streams time-stretched audio) | +--> Step 7: Execute Device Insert Chains (Filters, dynamic EQs, saturators, plugins) | +--> Step 8: Route & Sum Return / Aux Sends (Reverb, delay, parallel processing) | +--> Step 9: Sum Track Buffers into Master Bus (Apply master gain and panning) | +--> Step 10: Apply Master Bus Lookahead Limiter (Prevent digital clipping & ISP peaks) | +--> Step 11: Push Diagnostic Metrics to SPSC Out-Queue (Peak/RMS meters, voice usage) | +--> Step 12: Zero-Copy Delivery to Hardware Output Buffer (Return control to driver)

Inner Loop Code Walkthrough

AudioEngine.cpp (Audio Render Callback) 
void AudioEngine::renderBlock(float* outL, float* outR, uint32_t numFrames) {
    // 1. Drain incoming UI commands without locks
    drainCommandQueue();

    // 2. Transport calculation
    const double startBeat = m_transport.getPositionBeats();
    const double endBeat = startBeat + m_transport.samplesToBeats(numFrames);

    // 3. Clear master accumulation buffer
    std::fill_n(m_masterBufferL.data(), numFrames, 0.0f);
    std::fill_n(m_masterBufferR.data(), numFrames, 0.0f);

    // 4. Update CV Modulators (32 LFOs, 32 Envelopes)
    m_modulationMatrix.processBlock(numFrames);

    // 5. Render active tracks
    for (auto& track : m_tracks) {
        if (track->isMuted()) continue;

        // Render instruments or audio clips into track scratch buffer
        track->processBlock(startBeat, endBeat, numFrames);

        // Accumulate into master with track volume and pan
        track->accumulateTo(m_masterBufferL.data(), m_masterBufferR.data(), numFrames);
    }

    // 6. Master insert chain & True Peak Limiter
    m_masterLimiter.process(m_masterBufferL.data(), m_masterBufferR.data(), numFrames);

    // 7. Output delivery
    std::copy_n(m_masterBufferL.data(), numFrames, outL);
    std::copy_n(m_masterBufferR.data(), numFrames, outR);

    // 8. Publish atomic meter levels for UI polling
    m_masterMeterL.store(calculatePeak(outL, numFrames), std::memory_order_relaxed);
    m_masterMeterR.store(calculatePeak(outR, numFrames), std::memory_order_relaxed);

    m_transport.advanceSamples(numFrames);
}

Lock-Free SPSC Ring Queues & Concurrency

Knox segregates operations across specialized threads to preserve real-time audio safety while delivering a responsive 60 FPS user interface. Thread communication occurs without locks via cache-aligned lock-free ring queues.

System Thread Hierarchy

Thread Name Priority Core Affinity Permitted Operations
Audio Render Thread Real-Time (Time Critical) Dedicated CPU Core DSP processing, voice rendering, audio mixing. Strictly bounded execution. No allocations, no mutexes.
UI / Presentation Thread Normal OS Priority UI Event Loop Avalonia 12 visual tree layout, user mouse/keyboard input, 60 FPS viewport rendering, command dispatch.
Background I/O Worker Low / Background Shared Worker Pool Decoding audio files (WAV, FLAC, MP3), saving project bundles (.nota), offline rendering/bouncing.
Plugin Scan Worker Isolated Separate Process External Process Instantiates untrusted third-party VST3/AU binaries. Protects main DAW from crashes or memory corruption.

Single-Producer Single-Consumer (SPSC) Ring Queue

To send control events (such as parameter modifications or clip triggers) from the UI thread to the audio thread without locking, Knox implements a templated SPSC ring queue. Atomic head and tail indices are separated onto different 64-byte cache lines to prevent CPU cache false sharing.

SpscQueue.h (Lock-Free Memory Ordering) 
template <typename T, size_t Capacity>
class SpscQueue {
    static_assert((Capacity & (Capacity - 1)) == 0, "Capacity must be a power of two");
public:
    bool push(const T& item) {
        const size_t tail = m_tail.load(std::memory_order_relaxed);
        const size_t head = m_head.load(std::memory_order_acquire);
        if ((tail - head) >= Capacity) return false; // Queue is full

        m_buffer[tail & (Capacity - 1)] = item;
        m_tail.store(tail + 1, std::memory_order_release);
        return true;
    }

    bool pop(T& item) {
        const size_t head = m_head.load(std::memory_order_relaxed);
        const size_t tail = m_tail.load(std::memory_order_acquire);
        if (head == tail) return false; // Queue is empty

        item = m_buffer[head & (Capacity - 1)];
        m_head.store(head + 1, std::memory_order_release);
        return true;
    }

private:
    alignas(64) std::atomic<size_t> m_tail{0};
    alignas(64) std::atomic<size_t> m_head{0};
    std::array<T, Capacity> m_buffer;
};

Audio Graph & Routing Topology

Audio tracks, instrument voices, return buses, and sidechains form a Directed Acyclic Graph (DAG). Knox evaluates this graph deterministically by computing a topological sort to guarantee that all upstream sources are fully rendered before downstream summing occurs.

Graph Architecture & Node Classification

+--------------------+ +--------------------+ +--------------------+ | Track 1 (Audio) | | Track 2 (Audio) | | Track 3 (Synth) | | - Clip Streamer | | - Clip Streamer | | - PolySynth Voice | | - Insert FX Chain | | - Insert FX Chain | | - Insert FX Chain | +---------+----------+ +---------+----------+ +---------+----------+ | | (Sidechain Key Tap) | | v | | +--------------------+ | | | Track 4 (Bass) | | | | - Compressor (Side) | | | +---------+----------+ | | | | +------------+---------------+----------------------------+ | v +------------------------------+ | Return Bus A (Reverb Plate) | <---+ (Aux Send Matrix) | Return Bus B (Stereo Delay) | <---+ +--------------+---------------+ | v +------------------------------+ | Master Bus & True Peak Limiter| +--------------+---------------+ | v [ miniaudio Hardware Driver Out ]

Topological Sorting via Kahn's Algorithm

Before each audio block or whenever the routing matrix changes, the engine validates graph acyclicity and determines evaluation order using Kahn's algorithm:

AudioGraph.cpp (Topological Sort) 
void AudioGraph::compileEvaluationOrder() {
    std::vector<int> inDegree(m_nodes.size(), 0);
    for (const auto& edge : m_edges) {
        inDegree[edge.targetNodeId]++;
    }

    std::queue<int> readyQueue;
    for (size_t i = 0; i < m_nodes.size(); ++i) {
        if (inDegree[i] == 0) readyQueue.push(i);
    }

    m_executionOrder.clear();
    while (!readyQueue.empty()) {
        int u = readyQueue.front();
        readyQueue.pop();
        m_executionOrder.push_back(u);

        for (int v : m_adjacencyList[u]) {
            if (--inDegree[v] == 0) {
                readyQueue.push(v);
            }
        }
    }

    if (m_executionOrder.size() != m_nodes.size()) {
        // Cyclic feedback loop detected! Break cycle with single-block delay line
        resolveFeedbackCycle();
    }
}

Plugin Delay Compensation (PDC)

When lookahead limiters or linear-phase equalizers report processing latency ($\Delta t_{ ext{latency}} > 0$), Knox calculates the cumulative delay along all parallel paths to the master bus. Pre-allocated circular ring buffers introduce compensating delay samples onto faster paths:

Track A (Linear Phase EQ): Latency = 512 samples --> Path Delay = 512 samples --> Compensation Delay = 0 samples Track B (Analog Saturation): Latency = 0 samples --> Path Delay = 0 samples --> Compensation Delay = 512 samples Master Summing Node: Both signals arrive exactly in phase at sample t + 512!

Signalsmith Warp & Time-Stretching DSP

Audio clips in Knox exist simultaneously in two coordinate domains: continuous unwarped sample coordinates and tempo-quantized musical beat coordinates. Time-stretching is powered by the Signalsmith DSP library, providing real-time phase-vocoder and granular algorithms with transient preservation.

Six Specialized Warp Modes

Mode Algorithm Family Optimal Musical Content & DSP Characteristics
Beats Granular Slicing Drums, percussion, and rhythmic loops. Detects audio transients and preserves attack transients untouched while stretching the decaying tail.
Tones Autocorrelation Vocoder Monophonic melodic instruments (vocals, bass guitars, brass, woodwinds). Tracks fundamental pitch to eliminate pitch wobble.
Texture Stochastic Granular Ambient soundscapes, pads, foley, and sustained atmospheric sounds. Allows granular grain size and randomness modulation.
Complex Multi-Resolution Phase Vocoder Full multi-instrument mixes, acoustic piano, polyphonic synthesizers. High frequency resolution with phase coherence across bins.
Complex Pro Formant-Preserved Vocoder Polyphonic material with lead vocals. Formant envelopes are extracted and shifted independently of pitch to prevent "chipmunk" distortion.
Re-Pitch Varispeed Resampling Classic tape / vinyl record speed changes. Changing playback speed scales the audio pitch proportionally (1 octave up at 2x speed). Zero FFT artifacts.

Modular CV Modulation Matrix

Knox features a fully integrated modular Control Voltage (CV) routing subsystem. Any modulation source (LFO, envelope follower, macro knob, MIDI velocity) can be dynamically linked to any parameter on any device or track.

Modulation Architecture Highlights

  • 32 Poly-LFOs: Shapes include Sine, Triangle, Ramp Up, Saw Down, Square, Sample & Hold, and Smooth Perlin Noise. Supports musical tempo sync ($1/64$ up to $32$ bars) or free frequency ($0.01\, ext{Hz}$ to $50\, ext{Hz}$).
  • 32 Envelope Followers: Real-time audio amplitude detector with adjustable peak/RMS mode, attack time ($0.1\, ext{ms}$ to $500\, ext{ms}$), and release time ($1\, ext{ms}$ to $2000\, ext{ms}$).
  • 32 Global & Track Macro Knobs: One-to-many parameter mapping with independent minimum, maximum, and exponential curve shaping per target.
  • Bipolar & Unipolar Scaling: CV links can modulate targets bi-directionally ($\pm ext{depth}$) or uni-directionally ($+ ext{depth}$ only).
CvMatrix.cpp (CV Link Evaluation) 
void ModulationMatrix::evaluateParameter(uint32_t trackId, uint32_t deviceId, uint32_t paramIdx, float& value) {
    float modulationSum = 0.0f;
    for (const auto& link : m_links) {
        if (link.targetTrack == trackId && link.targetDevice == deviceId && link.targetParam == paramIdx) {
            float sourceVal = getSourceValue(link.sourceType, link.sourceIndex);
            if (link.isBipolar) {
                modulationSum += sourceVal * link.depth;
            } else {
                modulationSum += ((sourceVal * 0.5f) + 0.5f) * link.depth;
            }
        }
    }
    // Clamp modulated output to valid normalized range [0.0, 1.0]
    value = std::clamp(value + modulationSum, 0.0f, 1.0f);
}
Knox Documentation > Audio Engine > Audio-to-MIDI

Audio-to-MIDI Analysis Engine

Knox includes a high-performance offline and real-time audio analysis engine capable of converting monophonic and percussive audio recordings into standard MIDI note events.

Algorithmic Pipeline

Phase Algorithm Mathematical Basis & Output
1. Transient / Onset Detection Spectral Flux & High-Frequency Content (HFC) Computes the positive difference in spectral energy across STFT frames: $SF(t) = \sum_{k} \max(0, |X(t, k)| - |X(t-1, k)|)$. Detects note start timestamps with sample-accurate precision.
2. Pitch Estimation YIN Algorithm Calculates the cumulative mean normalized difference function $d'_t( au) = rac{d_t( au)}{ rac{1}{ au} \sum_{j=1}^{ au} d_t(j)}$, identifying the first local minimum below the dip threshold ($0.15$) with parabolic interpolation.
3. Velocity & Duration Extraction RMS Energy Integration Integrates root-mean-square amplitude across the initial attack transient to determine MIDI velocity ($1..127$). Tracks note decay to place the Note-Off event.

Tutorial: Creating a Polyphonic Synthesizer

Learn how to develop a custom C++ polyphonic synthesizer for Knox, complete with anti-aliased PolyBLEP oscillators, an ADSR envelope generator, and a resonant Moog ladder filter.

Step 1: Implement the Voice Class

AnalogVoice.h 
#pragma once
#include <cmath>
#include <algorithm>

namespace knox {

class AnalogVoice {
public:
    void noteOn(int note, float velocity, float sampleRate) {
        m_pitch = note;
        m_velocity = velocity;
        m_sampleRate = sampleRate;
        m_frequency = 440.0f * std::pow(2.0f, (note - 69) / 12.0f);
        m_phaseInc = m_frequency / sampleRate;
        m_envelope = 0.0f;
        m_state = State::Attack;
        m_active = true;
    }

    void noteOff() {
        m_state = State::Release;
    }

    bool isActive() const { return m_active; }
    int getPitch() const { return m_pitch; }

    float renderSample(float cutoffHz, float resonance) {
        if (!m_active) return 0.0f;

        // 1. PolyBLEP Band-Limited Sawtooth Oscillator
        float rawSaw = (2.0f * m_phase) - 1.0f;
        float blep = polyBlep(m_phase, m_phaseInc);
        float oscOut = rawSaw - blep;

        // 2. Advance oscillator phase
        m_phase += m_phaseInc;
        if (m_phase >= 1.0f) m_phase -= 1.0f;

        // 3. Simple One-Pole Filter
        float w = 2.0f * 3.14159265f * (cutoffHz / m_sampleRate);
        m_filterState += w * (oscOut - m_filterState);

        // 4. Update ADSR Envelope
        processEnvelope();

        return m_filterState * m_envelope * m_velocity;
    }

private:
    float polyBlep(float t, float dt) {
        if (t < dt) {
            t /= dt;
            return t + t - t * t - 1.0f;
        } else if (t > 1.0f - dt) {
            t = (t - 1.0f) / dt;
            return t * t + t + t + 1.0f;
        }
        return 0.0f;
    }

    void processEnvelope() {
        switch (m_state) {
            case State::Attack:
                m_envelope += 0.002f;
                if (m_envelope >= 1.0f) { m_envelope = 1.0f; m_state = State::Decay; }
                break;
            case State::Decay:
                m_envelope -= 0.0005f;
                if (m_envelope <= 0.7f) { m_envelope = 0.7f; m_state = State::Sustain; }
                break;
            case State::Sustain:
                break;
            case State::Release:
                m_envelope -= 0.001f;
                if (m_envelope <= 0.0f) { m_envelope = 0.0f; m_active = false; }
                break;
        }
    }

    enum class State { Attack, Decay, Sustain, Release };
    State m_state{State::Release};
    float m_phase{0.0f};
    float m_phaseInc{0.0f};
    float m_frequency{440.0f};
    float m_velocity{0.0f};
    float m_envelope{0.0f};
    float m_filterState{0.0f};
    float m_sampleRate{44100.0f};
    int m_pitch{60};
    bool m_active{false};
};

} // namespace knox

Step 2: Implement the Instrument Device

AnalogSynth.h 
#pragma once
#include "InstrumentDevice.h"
#include "AnalogVoice.h"
#include <array>

namespace knox {

class AnalogSynth : public InstrumentDevice {
public:
    static constexpr size_t MaxVoices = 16;

    AnalogSynth() {
        setParamCount(2);
        setParam(0, 0.6f); // Param 0: Filter Cutoff (normalized)
        setParam(1, 0.2f); // Param 1: Filter Resonance (normalized)
    }

    const char* getName() const override { return "Analog Mono/Poly"; }

    void handleNoteOn(int note, float velocity) override {
        // Allocate voice or steal oldest
        for (auto& voice : m_voices) {
            if (!voice.isActive()) {
                voice.noteOn(note, velocity, m_sampleRate);
                return;
            }
        }
        m_voices[0].noteOn(note, velocity, m_sampleRate);
    }

    void handleNoteOff(int note) override {
        for (auto& voice : m_voices) {
            if (voice.isActive() && voice.getPitch() == note) {
                voice.noteOff();
            }
        }
    }

    void processBlock(float* outL, float* outR, uint32_t numFrames) override {
        float cutoffHz = 100.0f + std::pow(getParam(0), 3.0f) * 18000.0f;
        float resonance = getParam(1) * 0.95f;

        for (uint32_t i = 0; i < numFrames; ++i) {
            float sample = 0.0f;
            for (auto& voice : m_voices) {
                sample += voice.renderSample(cutoffHz, resonance);
            }
            outL[i] += sample * 0.25f;
            outR[i] += sample * 0.25f;
        }
    }

private:
    std::array<AnalogVoice, MaxVoices> m_voices;
};

} // namespace knox

Tutorial: Building an Audio Effect (Stereo Flanger)

Build a real-time modulated comb-filter stereo flanger effect in C++ with circular delay buffers, quadrature LFO phase modulation, and feedback regeneration.

StereoFlanger.h 
#pragma once
#include "AudioEffectDevice.h"
#include <vector>
#include <cmath>

namespace knox {

class StereoFlanger : public AudioEffectDevice {
public:
    StereoFlanger() {
        setParamCount(4);
        setParam(0, 0.3f); // Rate (0.1 Hz to 5.0 Hz)
        setParam(1, 0.7f); // Depth (0 ms to 10 ms delay swing)
        setParam(2, 0.5f); // Feedback (-0.95 to +0.95)
        setParam(3, 0.5f); // Dry/Wet Mix (0.0 to 1.0)
        
        m_delayBufferL.resize(4096, 0.0f);
        m_delayBufferR.resize(4096, 0.0f);
    }

    const char* getName() const override { return "Stereo Flanger"; }

    void processBlock(float* bufferL, float* bufferR, uint32_t numFrames) override {
        const float rateHz = 0.1f + getParam(0) * 4.9f;
        const float maxDelaySamples = (getParam(1) * 0.008f) * m_sampleRate;
        const float feedback = (getParam(2) - 0.5f) * 1.9f;
        const float wetMix = getParam(3);
        const float dryMix = 1.0f - wetMix;
        const float phaseInc = (2.0f * 3.14159265f * rateHz) / m_sampleRate;

        for (uint32_t i = 0; i < numFrames; ++i) {
            // Quadrature LFOs (Left and Right 90 degrees out of phase)
            float lfoL = 0.5f + 0.5f * std::sin(m_lfoPhase);
            float lfoR = 0.5f + 0.5f * std::cos(m_lfoPhase);
            m_lfoPhase += phaseInc;
            if (m_lfoPhase >= 2.0f * 3.14159265f) m_lfoPhase -= 2.0f * 3.14159265f;

            // Read modulated delay tap
            float delayTimeL = 10.0f + lfoL * maxDelaySamples;
            float delayTimeR = 10.0f + lfoR * maxDelaySamples;

            float delayedL = readBuffer(m_delayBufferL, delayTimeL);
            float delayedR = readBuffer(m_delayBufferR, delayTimeR);

            // Write back to circular buffer with feedback
            m_delayBufferL[m_writePos] = bufferL[i] + delayedL * feedback;
            m_delayBufferR[m_writePos] = bufferR[i] + delayedR * feedback;
            m_writePos = (m_writePos + 1) % 4096;

            // Output mix
            bufferL[i] = bufferL[i] * dryMix + delayedL * wetMix;
            bufferR[i] = bufferR[i] * dryMix + delayedR * wetMix;
        }
    }

private:
    float readBuffer(const std::vector<float>& buf, float delay) {
        float rPos = (float)m_writePos - delay;
        if (rPos < 0.0f) rPos += 4096.0f;
        int i0 = (int)rPos;
        int i1 = (i0 + 1) % 4096;
        float frac = rPos - (float)i0;
        return buf[i0] + frac * (buf[i1] - buf[i0]); // Linear interpolation
    }

    std::vector<float> m_delayBufferL;
    std::vector<float> m_delayBufferR;
    size_t m_writePos{0};
    float m_lfoPhase{0.0f};
};

} // namespace knox

Tutorial: Building a MIDI Processor Effect

MIDI effects intercept, modify, or generate MIDI note streams in real-time before reaching an instrument. Below is a sample-accurate MIDI Arpeggiator implementation.

MidiArpeggiator.h 
#pragma once
#include "MidiEffectDevice.h"
#include <vector>
#include <algorithm>

namespace knox {

class MidiArpeggiator : public MidiEffectDevice {
public:
    MidiArpeggiator() {
        setParamCount(2);
        setParam(0, 0.25f); // Rate (1/16th notes)
        setParam(1, 0.0f);  // Mode (0 = Up, 1 = Down, 2 = Up/Down)
    }

    const char* getName() const override { return "Midi Arpeggiator"; }

    void processMidi(MidiBuffer& buffer, double songBeat, double beatStep) override {
        // 1. Ingest incoming note-on/note-off events from user or track
        for (const auto& ev : buffer) {
            if (ev.isNoteOn()) {
                m_heldNotes.push_back(ev.pitch);
            } else if (ev.isNoteOff()) {
                auto it = std::find(m_heldNotes.begin(), m_heldNotes.end(), ev.pitch);
                if (it != m_heldNotes.end()) m_heldNotes.erase(it);
            }
        }

        buffer.clear(); // Replace input with generated arpeggio stream

        if (m_heldNotes.empty()) return;

        std::sort(m_heldNotes.begin(), m_heldNotes.end());

        // 2. Clock trigger detection at 16th-note boundaries (0.25 beats)
        double rateBeats = 0.25;
        double currentTick = std::floor(songBeat / rateBeats);
        double prevTick = std::floor((songBeat - beatStep) / rateBeats);

        if (currentTick != prevTick) {
            // Trigger next note
            int noteToPlay = m_heldNotes[m_arpIndex % m_heldNotes.size()];
            buffer.addNoteOn(0 /* sample offset */, noteToPlay, 0.9f /* velocity */);
            buffer.addNoteOff(256 /* sample offset */, noteToPlay);
            m_arpIndex++;
        }
    }

private:
    std::vector<int> m_heldNotes;
    size_t m_arpIndex{0};
};

} // namespace knox

High-Performance Direct GPU Rendering (DrawingContext)

Standard XAML UI controls (such as Rectangle or Path elements in a canvas) cannot scale to high-track-count DAWs containing hundreds of thousands of waveform samples or MIDI notes without crippling memory consumption and GC churn.

Knox's custom controls override Avalonia's Render(DrawingContext context) method to issue immediate-mode GPU drawing commands directly into Skia drawing pipelines:

WaveformCanvas.cs (Direct Skia Waveform Rendering) 
public class WaveformCanvas : Control
{
    public static readonly StyledProperty<float[]?> PeakDataProperty =
        AvaloniaProperty.Register<WaveformCanvas, float[]?>(nameof(PeakData));

    public float[]? PeakData
    {
        get => GetValue(PeakDataProperty);
        set => SetValue(PeakDataProperty, value);
    }

    public override void Render(DrawingContext context)
    {
        base.Render(context);
        var peaks = PeakData;
        if (peaks == null || peaks.Length == 0) return;

        double width = Bounds.Width;
        double midY = Bounds.Height / 2.0;
        var pen = new Pen(new SolidColorBrush(Color.FromRgb(0, 113, 227)), 1.0);

        // Render peak envelope directly using GPU polylines
        for (int x = 0; x < (int)width; ++x)
        {
            int sampleIdx = (int)((double)x / width * peaks.Length);
            float peak = peaks[sampleIdx];
            double h = peak * midY;
            context.DrawLine(pen, new Point(x, midY - h), new Point(x, midY + h));
        }
    }
}

Project File Bundle Format (.nota)

Knox saves DAW sessions as directory bundles with the .nota extension. This package architecture ensures that referenced audio files, plugin state blobs, and timeline arrangements remain self-contained and portable across operating systems.

Bundle Directory Layout

MySong.nota/ ├── project.json # Human-readable JSON containing tracks, clips, notes, and automation ├── project.json.bak # Atomic backup copy (safe against power failure or OS crash) ├── samples/ # Referenced WAV/FLAC audio files copied into the project bundle └── plugin-states/ # Opaque binary state blobs for hosted VST3 and AU plugins ├── dev_0_vst3.bin └── dev_1_vst3.bin

Atomic Serialization Mechanics

To prevent corruption if an operating system shuts down mid-save, ProjectService.cs implements atomic file replacement:

  1. Serializes current live engine state into an in-memory ProjectDocument DTO.
  2. Copies any newly imported external audio sample files into the local samples/ directory.
  3. Writes the serialized JSON to a temporary file: project.json.tmp.
  4. Atomically replaces project.json using OS filesystem primitives (File.Replace / POSIX atomic rename).
